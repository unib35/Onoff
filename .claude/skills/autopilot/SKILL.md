# 자율 진행

이 스킬은 사용자가 **이번 세션에서 직접 맡겼을 때만** 쓴다. 허락 범위(병합까지인지 PR까지인지, 대상 이슈, 끝낼 시각 · 개수)를 시작할 때 한 번 확인하고 `docs/progress/README.md`에 적는다. 묻지 못하면 **PR까지만** 하고 병합하지 않는다.

## 0. 시작
1. `sh .claude/skills/finish-feature/scripts/verify.sh claude` 와 `git status`로 시작 상태를 확인한다. 커밋하지 않은 변경이 있으면 건드리지 않고 멈춘다(사용자 작업일 수 있다).
2. 대상 이슈: 사용자가 준 목록, 없으면 `gh issue list -R <GH_REPO> --label "자율 진행" --state open`. 의존 순서(먼저 필요한 것)대로 줄 세운다. `결정 필요` · `차단` · `고위험` · `디자인 필요` 라벨은 빼고 목록에 「건너뜀」으로 적는다.

## 1. 이슈 하나씩 (반복)
1. **시작** — `start-feature` 절차. 갈라질 곳은 Git 전략을 따른다.
2. **나누기** — `docs/conventions/architecture.md`의 에이전트 구성과 `docs/conventions/agents.md`의 순서(계층 구조면 계약 먼저 → 병렬 → 조립). 병렬은 2개까지, 시뮬레이터 · 포트 · 빌드 폴더를 나눈다.
3. **회수 · 확인** — 에이전트 보고를 믿지 않는다: `git diff --stat origin/<BASE_BRANCH>...<branch>`로 보고한 파일 · 테스트가 실제로 있는지, 소유 경로 안인지.
4. **검증** — `check.sh` → `verify.sh <areas> arch`. **종료 코드를 따로 확인한다.** 검증과 PR · 병합을 `;`로 한 줄에 잇지 않는다(실패한 채 병합된 사고가 있었다). 실패하면 고쳐서 다시, 같은 원인으로 2번 실패하면 그 이슈를 멈춘다.
5. **리뷰** — `reviewer`. 「수정 필요」면 고치고 다시 검증. 「차단」이면 멈춘다.
6. **PR** — `finish-feature` 절차의 본문 형식. 승인 질문 대신 시작할 때 받은 허락을 따른다.
7. **병합(허락된 경우만)** — CI 통과 확인 → 저장소의 병합 방식. 병합 후 기준 브랜치에서 `verify.sh`를 다시 돌리고 실패하면 다음 이슈로 가지 않는다. git-flow의 release · hotfix는 되돌림 병합 PR까지.
8. **기록** — `docs/progress/README.md`에 한 줄(이슈 · PR · 검증 결과 · 멈춘 것).

## 멈추고 기록만 하는 것 (결정하지 않는다)
- 디자인 · 문구 · 기획과 다르게 만들어야 하는 것, 아키텍처 · 라이브러리 변경
- 규칙 · 계산이 문서끼리 다르거나 비어 있음 → 이슈에 `결정 필요` 라벨 + 선택지 · 추천을 댓글로
- 결제 · 운영 데이터 · 운영 배포 · 권한 확대 · 비밀값 · force push · 기록 다시 쓰기
- 같은 이슈 2번 연속 실패, 원인을 모르는 테스트 실패

멈춘 이슈는 브랜치를 그대로 두고 다음 이슈로 넘어간다. 앞 이슈에 의존하는 이슈는 함께 건너뛴다.

## 길게 돌릴 때
- 컨텍스트가 길어지면 이슈 경계에서 진행 로그를 먼저 쓰고 이어간다.
- 오래 기다릴 외부 작업(CI)은 짧은 간격으로 반복 확인하지 않는다 — 걸리는 시간에 맞춰 한 번.

## 끝낼 때 (아침 보고)
`docs/progress/README.md` 맨 아래에 묶음 요약을 쓰고, 사용자에게 같은 순서로 보고한다:
수행(끝낸 이슈 · PR 링크) / 검증(실행한 명령 · 결과) / 차단(멈춘 이슈 · 이유) / 내가 할 일(결정 필요 목록, 화면 차이로 쉽게 설명 + 추천) / 다음 단계.
